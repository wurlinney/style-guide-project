# Шаблоны документов

## П11. Пользовательская инструкция

Пользовательская инструкция содержит заголовок действия, назначение, условия начала работы, нумерованные шаги, наблюдаемый результат и раздел «Если действие недоступно». Последний раздел обязателен для описания предусмотренных блокирующих ситуаций, например отсутствия заданий по выбранным фильтрам. Для каждой ситуации укажите признак и способ продолжить работу. Если ограничений в рассматриваемом сценарии нет, автор фиксирует это при проверке.

## П12. Учебное задание и разбор

Карточка задания содержит название, аудиторию и необходимые знания, условие, формат и ограничения входных данных, ожидаемый результат и примеры. В условии явно определяйте поведение для пустого ввода и нескольких допустимых результатов либо объясняйте, почему такой случай исключён. Эти сведения должны быть доступны до начала решения.

Разбор размещайте после условия и примеров, под отдельным заголовком. Его шаблон: идея решения; последовательность рассуждений; код с версией среды, если он нужен; проверки; временная и пространственная сложность с пояснением обозначений; типичные ошибки. Для теоретического вопроса вместо кода приводите ответ и обоснование. Неприменимые разделы не заполняйте формально.

## П13. Программный интерфейс

Описание программного интерфейса содержит назначение операции; метод и путь обращения; требования к доступу; параметры с типами, обязательностью и ограничениями; пример запроса; структуру успешного ответа; возможные ошибки с кодами и действиями клиента. Отличайте отсутствие поля от его пустого значения. Примеры сверяйте с контрактом продукта; не придумывайте несуществующие параметры.

## П14. Руководство разработчика

Руководство разработчика содержит цель; поддерживаемую среду и версии зависимостей; предварительную настройку; команды запуска; ожидаемый результат; команды проверок и способы исправить типичные ошибки. Указывайте рабочую папку для команды, если она имеет значение. Секретные значения не включайте; обязательные переменные окружения поясняйте. Если шаг изменяет данные, описывайте его последствия до команды.
